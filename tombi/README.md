# טומבי: אווטאר טיפולי מונחה פעילויות

מערכת דפדפן (Chrome) לילדים בגילאי 3–6. האווטאר טומבי מוביל פעילויות טיפוליות, מדבר ומזיז את הפה, מקשיב לילד, ומודד **מתי**, **כמה חזק**, **כמה ארוך** ו**כמה פעמים**, בלי לנסות להבין מילים. המערכת עוקבת אחר התקדמות ומטרות שאושרו בידי מטפל/ת ומציעה התאמות לתוכנית; ההחלטות נשארות בידי איש/אשת המקצוע. כל הניתוח רץ בדפדפן, ושום הקלטה של ילד לא נשמרת.

## מה צריך להתקין

1. **Google Chrome**
2. **VS Code**
3. בתוך VS Code, תוסף אחד: **Live Server** (של Ritwick Dey)

זה הכול. לא צריך Python, לא Streamlit ולא npm.

## איך מריצים

1. פותחים את התיקייה `tombi` ב-VS Code: ‏File ← Open Folder.
2. מתקינים את Live Server: לוחצים `Ctrl+Shift+X`, מחפשים **Live Server**, ולוחצים Install.
3. לוחצים קליק ימני על `index.html` ובוחרים **Open with Live Server**.
4. Chrome נפתח בכתובת כמו `http://127.0.0.1:5500`. במסך ההכנה לוחצים **מיקרופון** ומאשרים גישה.

**צפייה מיידית בדוח הדגמה:** אחרי הפעלת Live Server פותחים את [http://127.0.0.1:5500/index.html?demo=1](http://127.0.0.1:5500/index.html?demo=1). הדוח נפתח עם חמישה מפגשים סינתטיים וגרפי התקדמות. נתוני ההדגמה נשמרים בדפדפן, מסומנים בבירור כנתוני דוגמה ואינם משנים נתונים קיימים.

בכרטיסי הילדים ציון המפגש האחרון מוצג מתוך 100, לצד ההפרש מהמפגש הקודם עם ציון ומהמפגש הראשון עם ציון. התרשים מציג את ציוני המפגשים על אותו ציר 0–100; הציון המסכם הוא ממוצע של עד ארבעה מדדי פעילות.

המיקרופון עובד רק בכתובת `localhost` / `127.0.0.1` או ב-https. לכן פותחים דרך Live Server ולא בלחיצה כפולה על הקובץ.

**טלפון וטאבלט:** הממשק מותאם למסכי מגע, ובמהלך מפגש פאנל הסייעת נפתח כמגירה תחתונה כדי להשאיר את בחירות הילד נגישות. כדי שהמיקרופון יעבוד ממכשיר אחר, צריך לפתוח את האתר ב־HTTPS; כתובת רשת מקומית כמו `http://192.168.x.x` לא מספיקה.

### פרסום קישור ציבורי דרך Google Firebase

האתר הראשי הפעיל הוא https://leewainbergs.github.io/ocupa_game/ ומתפרסם אוטומטית לאחר push ל־`main` ובדיקות GitHub Actions מוצלחות. הפרסום נבנה באמצעות `node tombi/dev/build-site.cjs <new-output-directory>`: קובצי HTML מפנים לנכסים עם hash תוכן למניעת שימוש בגרסה ישנה מהמטמון, ו־`release.json` כולל את מזהה ה־commit שפורסם. קובצי פיתוח, תיעוד ודוחות סינתטיים לדוגמה נשמרים ב־Git אך אינם נכללים באתר הנבנה.

אתר בדיקות הסנכרון הוא https://tombi-synthetic-297488300955.web.app/. יש לפרסם בו מאותו commit ומאותו build, עם config סינתטי ופס אזהרה בלבד כהבדלים מכוונים. push ל־GitHub אינו מפרסם אוטומטית ל־Firebase. לאחר פרסום יש לוודא ש־`release.json` בשני האתרים מציג אותו commit. בהרצת כמה צ׳אטים באותה תיקייה יש לרכז את הפרסום בצ׳אט אחד לאחר עצירת העריכות האחרות; לעבודה מקבילה מבודדת משתמשים ב־Git worktrees.

האתר מוגדר לפרסום ב־Firebase Hosting. קובצי הפיתוח והתיעוד מוחרגים מהפרסום. כדי ליצור את הקישור הציבורי:

1. נכנסים ל־[Firebase Console](https://console.firebase.google.com/) עם חשבון Google, יוצרים פרויקט Firebase חדש ורושמים את מזהה הפרויקט (Project ID).
2. פותחים PowerShell בתיקיית הפרויקט הראשית, זו שמכילה את `firebase.json`, ומתחברים:

   ```powershell
   npx firebase-tools login
   npx firebase-tools use --add
   ```

   בוחרים את הפרויקט שיצרתם. הפקודה תשמור את הקישור לפרויקט בקובץ `.firebaserc`.
3. מפרסמים:

   ```powershell
   npx firebase-tools deploy --only hosting
   ```

   בסיום תוצג כתובת HTTPS ציבורית, בדרך כלל `https://<project-id>.web.app`.

הפקודה הראשונה עשויה להציע הורדה זמנית של Firebase CLI באמצעות npm. אין צורך להכניס סיסמה לקוד או לשלוח אותה לאף אחד; ההתחברות מתבצעת בחלון Google. ללא הגדרת סנכרון הענן, פרופילי הילדים והמפגשים נשמרים ב־localStorage בדפדפן של כל מכשיר ואינם משותפים או מסונכרנים בין מכשירים. לפני שימוש בנתונים אמיתיים, יש להוריד גיבוי מהמכשיר שבו הנתונים נשמרים.

### סנכרון צוות והורים

בקוד קיימים מסך צוות לסנכרון ילדים, מפגשי משחק והזמנות, ומסך הורים ב־`parent.html`. הסנכרון **כבוי כברירת מחדל ובאתר הראשי**: כתובת API ופרטי Firebase Web App אינם מוגדרים ב־`js/cloud-config.js`. בצד Ocupa נבנה ונפרס שירות משחק נפרד לבדיקות סינתטיות בלבד, עם מסד וסודות נפרדים ו־Firebase Authentication עם Google. כניסה אמיתית ובדיקות הרשאות מול המסד נבדקו; בדיקת שני מכשירים ושני חשבונות Google אמיתיים עדיין נדרשת. אישור פרטיות למידע ילדים אמיתי עדיין ממתין. אין לחבר את האתר הראשי למסד הבדיקות או להשתמש בנתוני ילדים אמיתיים. `ocupa-poc-api` הקליני נשאר פרטי ואסור לפתוח אותו לציבור. השירות מאמת Firebase ID tokens בצד השרת, ושום סוד שרת או מפתח הצפנה אינו נכלל בפרונט.

לאחר הקמת endpoint מאומת ואישור הפעלה, הצוות יתחבר ב-Google, יקשר ידנית פרופיל משחק לתיק ילד/ה ב-Ocupa, ויוכל לשלוח קוד חד-פעמי (7 ימים) לכתובת Google מאומתת. כמה אפוטרופוסים יכולים להתחבר בנפרד; הצוות יכול לבטל קישור או הרשאה. מפגשי הורים ממתינים לאישור צוות, ושינויי שלבים מוחלים בענן רק באישור מפורש. נשלחים רק פרטי משחק וציוני משימות הדרושים לתפעול; אודיו, טביעות קול, MFCC, תוכניות והערות קליניות אינם מסתנכרנים. הקלטות אינן נשמרות.

לבדיקת הסנכרון עם נתונים סינתטיים מריצים מתיקיית המאגר `node --test tombi/dev/cloud-sync.test.cjs` (נדרש Node.js 22 ומעלה). הבדיקות אינן דורשות חיבור לענן. הן רצות גם לפני פרסום GitHub Pages, אך אינן מחליפות בדיקת כניסה אמיתית, מסד נתונים ושני מכשירים לפני אישור הפעלה.

## הקול של טומבי

- טומבי משתמש בקול עברי שמותקן במחשב. ב-Windows: הגדרות ← זמן ושפה ← דיבור ← הוספת קולות ← עברית, ואז מפעילים מחדש את Chrome. באנדרואיד: הגדרות ← נגישות ← המרת טקסט לדיבור ← Google ← עברית.
- **מומלץ:** במסך ההגדרות אפשר להקליט כל שורה של טומבי בקול שלך. שורה מוקלטת מחליפה את הקול הממוחשב, והפה של טומבי זז לפי ההקלטה. השורות מופיעות שם אחרי שטומבי אמר אותן פעם אחת, אז כדאי להריץ קודם מפגש אחד בסימולציה.
- גם בלי קול עברי הפעילויות פועלות: הטקסט מופיע בבועה והפה זז.

## המפגש (8–10 דקות)

בתחילת מפגש טומבי מכייל את רעש הרקע, משמיע סמני קול לבדיקת השהיית הרמקול, ומבקש שלוש רקיעות ושלוש מחיאות כדי לכייל את זיהוי הצלילים. הכיול אינו מקבל ציון.

| שלב | מה מודדים | תחום |
|---|---|---|
| 1. שאלה על התחושה ונשימת דרקון לבחירה | דיווח עצמי על תחושה; הילד בוחר אם לנשום נשימה אחת, שלוש או חמש | זיהוי תחושה ובחירה בכלי הרגעה |
| 2. הד קולי | מספר הברות או מחיאות, וסטייה בזמן במילישניות | תזמון ורצף |
| 3. עכבר ואריה | פי כמה האריה חזק מהעכבר, ועקביות בין שני סבבים | הדרגה וויסות |
| 4. מילת הקסם | צפרדעים שנתפסו, תגובות מיותרות, זמן תגובה | קשב ועכבה |
| 5. נחש שקט | משך הסססס בשלושה ניסיונות | ויסות נשימה |
| 6. שאלה על התחושה בסיום | דיווח עצמי נפרד, בלי ציון או השוואה | שיתוף בתחושה |

הדיווחים על תחושה נשמרים כפי שהילד בחר, ללא ציון, דירוג או מסקנה על מצבו; התשובה אינה משנה את בחירת המשימות. נשימת הדרקון היא הזמנה קצרה ועדינה, הילד בוחר נשימה אחת, שלוש או חמש, ואפשר לעצור בכל רגע; אם אין תגובה במשך דקה, הפעילות מסתיימת. היא אינה מחליפה את משימת "נחש שקט" שבהמשך. הציונים שהוגדרו למשימות האחרות נשמרים יחד עם המדדים הגולמיים ורמת הביטחון בזיהוי. במצב עצירה ברמז של הנחש נשמר זמן העצירה כמדד גולמי בלבד; אין לו ציון סף לפני כיול בפיילוט. תוצאות עם ביטחון נמוך מ־60% מסומנות בדוח כזיהוי חלקי.

## תוכנית המפגש והמשימות

במסך ההכנה, בכרטיס **תוכנית המפגש**, אפשר לבחור חדר (קליניקה, בית או גן), תקציב של 6, 9 או 12 דקות, רצפה קשה, מרחב פנוי, סיר ושולחן, כדור וחדר שקט. אפשר להחליף משימה באותה משבצת, לדלג עליה, לנעוץ אותה למפגש הבא או ללחוץ **תכנון מחדש**. הכיול, שאלות התחושה ונשימת הדרקון הם חלקים קבועים. התכנון מתחשב בגיל, במסלול ללא מילים, ביכולת לקפוץ ולעמוד, בהיסטוריה ובמטרות שאושרו; משימה נחשבת כמשוחקת אם הופיעה באחד משלושת המפגשים האחרונים. נשמרת מגבלה של משימה חדשה אחת וקפיצה אחת, ונמנע רצף של שתי משימות תנועה בעמידה. בגן לא מוצעות משימת הכדור או רמות הלחישה. בכרטיס הילד אפשר להחריג משימות ולסמן רגישות לקול.

אומדן הזמן מחבר את משכי המשימות ו־15 שניות למעבר ביניהן. אם התוכנית חורגת מהתקציב, נבחרות תחילה גרסאות קצרות, ואז מוסרות משימת הדירוג ולבסוף משימת הקצב לפי הצורך.

בגרסאות המלאות המשימות המוטוריות כוללות כמה סבבים מדידים ולא רק רצף יחיד: קפיצות (4), פסל דרקון (5 עצירות), מצעד (8–12 פעימות ועוד 12 צעדים בהמשכיות), כף-רגל/סיר-שולחן (8), כדור (5), רגלי פיל/עכבר (4) והתוף ההפוך (16 פריטים, מהם 14 פריטי היפוך מנוקדים ברמות 2–5). צב וארנב כולל שני מקטעים ארוכים יותר לתרגול ההאטה. הגרסאות הקצרות מצמצמות את מספר הסבבים או את משך המקטע, והציונים בכל משימה מחושבים על פני הסבבים שבוצעו. במפגש חי אין השהיה מלאכותית כדי להגיע לאומדן; זמן התגובה בפועל תלוי בקצב הילד ובהנחיות.

| משימה | תחום ומדד עיקרי |
|---|---|
| שאלה על התחושה (תחילה ובסיום) | בחירה אישית של הילד; בתחילת המפגש אפשר לבחור משך לנשימת דרקון עדינה |
| הד קולי | חיקוי כמות הפעימות ותזמון |
| עכבר ואריה | דירוג עוצמת הקול; רמות מתקדמות כוללות מנהרת לחישה |
| מילת הקסם | תגובה למילת מטרה, תגובות מיותרות וזמן תגובה |
| נחש שקט | משך, יציבות והפסקות בצליל סססס |
| רוקעים ונעצרים | עצירה וחידוש תנועה |
| קפיצות הדרקון | ספירת נחיתות ועצירה במספר יעד |
| התוף ההפוך | חיקוי ראשוני, ואז עיכוב תגובה במספר הפוך לפעימות |
| צב וארנב | מעבר מקצב מהיר לאיטי |
| כף-רגל / סיר-שולחן | רצף ומעבר בין סוגי הקשה |
| כדור הדרקון | רצף הקפצות ועקביות |
| רגלי פיל ורגלי עכבר | דירוג עוצמת הרקיעה |
| מצעד הדרקון | סנכרון צעדים והמשכיות בלי פעימה |

התוכנית, המדדים הגולמיים והציונים של כל משימה נשמרים במפגש ומופיעים בדוח ובייצוא CSV.

**רמות מתקדמות:** מילת הקסם מתקדמת ממילת מטרה מול אותה מילה בקול איטי, למילים דומות, לצלילי פעמון/תוף/צפצוף, לתזמון לא סדיר, ולבסוף להחלפת כלל שמסומנת בכוכב או בירח. יחס המטרה הוא 9 מתוך 12; זמן תגובה נכנס לציון מגיל 4.5 בלבד. בתוף ההפוך, רמה 1 היא חיקוי; ברמות 2–5 שני פריטי החיקוי הראשונים משמשים טרום-מבחן שאינו מנוקד, ו־14 הפריטים הבאים נמדדים בהיפוך. רמה 2 מציגה רמז חזותי, רמה 3 מסירה אותו, רמה 4 מקצרת את המרווח, ורמה 5 משנה את המרווחים. בנחש, רמות 1–3 מודדות קיבולת (הטוב מבין שלושה), ורמות 4–5 מודדות זמן עצירה אחרי רמז; מדד העצירה מוצג ללא ציון מנורמל. במצעד, רמה 4 משנה את הטמפו באמצע, ואנטי-פאזה ברמה 5 מופעלת רק בגיל 5–6.

## משימות ריפוי בעיסוק מבוססות אודיו (מנוע OT)

שלוש משימות נוספות רצות על מנוע משותף (`js/tasks/ot-engine.js`). הן מבוססות רק על אודיו ותזמון, בלי מצלמה. החלוקה בין התפקידים שקופה:

- **הילד/ה והסייעת** מבצעים פעילות פיזית בחדר ומדווחים בקול קצר למיקרופון. הסייעת יכולה גם לסמן ידנית.
- **טומבי** נותן הוראות קצרות וחמות, סופר ומשקף התקדמות.
- **המערכת** אוספת רק מדדים כמותיים גולמיים. היא אינה נותנת ציון, אבחנה או פרשנות: `score` הוא `null` ו־`interpretation` הוא `null`.

| משימה | מהלך | מדדים עיקריים |
|---|---|---|
| מגדל הקריסטלים (`crystalTower`) | בונים מגדל קוביות ומדווחים בקול על כל קומה ("קומה 1 מוכנה!"). אפשר גם ללחוץ על "קומה N מוכנה". נקישות קוביות אינן נספרות כדיווח | `total_duration_sec`, `build_duration_sec`, `latency_sec[]`, `inter_response_time_sec[]` |
| שיקוי הרוגע (`calmingPotion`) | נשיפה או זמזום ארוכים "למילוי השיקוי", עד 15 שניות בכל ניסיון | `duration_sec` (הנשיפה הרציפה הארוכה), `exhale_duration_sec[]`, `audio_stability_score`, `amplitude_sd_db`, `pitch_stability_score`, `break_count_total` |
| מנחש הרגשות של טומבי (`emotionGuess`) | טומבי מספר סיפור קצר בטון רגשי, שואל "איך טומבי מרגיש?", מגיב, ושואל שאלת המשך. אין זיהוי דיבור; הסייעת יכולה לסמן את הרגש שהילד אמר | `latency_sec[]`, `followup_latency_sec[]`, `vocal_engagement_sec`, `utterances_total`, `adult_voice_sec` (בנפרד) |

**הגדרות מדידה:**

- `latency_sec` נמדד מסיום ההנחיה של טומבי, כולל 280 אלפיות השנייה של הגנת הד, ועד תחילת הקול התקף הראשון. אם הקול כבר נשמע כשנפתח חלון ההקשבה (הילד/ה דיבר/ה בזמן ההנחיה), זמן התגובה נרשם כ־`null` ולא כ־0, האירוע מסומן ב־`sound_at_window_open: true`, והספירה מופיעה ב־`responses_sounding_at_window_open`.
- `inter_response_time_sec` הוא המרווח בין תחילות של דיווחים עוקבים.
- `audio_stability_score` הוא חלק הפריימים, ב־80% האמצעיים של הנשיפה, שעוצמתם בטווח ±3 dB מהחציון.
- `pitch_stability_score` הוא החלק שנמצא בטווח ±1 חצי טון מהחציון. הוא מחושב רק כשיש לפחות 10 פריימים קוליים.
- קול מבוגר (מתחת לסף F0) אינו נכלל במדדי הילד ונרשם בנפרד.

את המשימות מוסיפים ידנית במסך ההכנה, דרך "הוספת משימת ריפוי בעיסוק". המתכנן האוטומטי אינו בוחר אותן. בדוח, הכפתור "ייצוא מדדי ריפוי בעיסוק (JSON)" מוריד קובץ במבנה `tombi.ot-dashboard/v1`, ובו לכל משימה רשומת `tombi.ot-task/v1`. הרשומה כוללת:

- תפקידים
- מדדים
- ניסיונות
- יומן אירועים עם חותמות זמן
- הגדרות המדדים

הרשומות הגולמיות נשמרות מקומית בלבד ואינן נשלחות בסנכרון הענן.

## מטרות טיפוליות, תכנון ודיווח

בכרטיס הילד אפשר להגדיר מטרות מתוך תבניות של תזמון ורצף, המתנה ועצירה, ויסות תנועה, דירוג עוצמה, תכנון ותיאום מוטורי וויסות נשימה וקול. לכל מטרה אפשר להגדיר נקודת התחלה ויעד מדיד, ולקשר אותה למשימות קיימות. סימון מטרה כמאושרת מחייב שם מטפל/ת.

המטרות שאושרו מוצגות לפני המפגש ומשפיעות על דירוג המשימות בתוכנית. התוכנית נשארת ניתנת לעריכה, ובמקרה שיש מטרות מאושרות נדרשת תיבת אישור מפורשת לפני התחלת המפגש. כל מפגש שומר אילו מטרות ותוכנית אושרו.

בדוח מופיעים המדידות התקפות והלא ודאיות, ביטחון המדידה, עזרה שניתנה, מגמה והצעה לעיון מקצועי. המערכת אינה משנה מטרה או מכריזה על השגתה אוטומטית; סימון כהושגה דורש פעולה מפורשת של מטפל/ת. אפשר גם לתעד תצפיות נפרדות מהבית, מהגן או מהקליניקה כדי לעקוב אחרי שימוש במיומנות מחוץ לאפליקציה. אלה דיווחים תיאוריים ולא מדידה אוטומטית.

הציונים והספים הם מדדים פנימיים של המשימות ואינם כלי אבחוני או תחליף לשיקול דעת מקצועי. שינוי בתנאי החדר, ברמת העזרה או בביטחון הזיהוי עשוי להשפיע על השוואת תוצאות.

**נתוני הדגמה:** בהגדרות ← נתונים ← "הוספת נתוני הדגמה (תום, בן, דן ונועה)" אפשר ליצור ארבעה פרופילים עם היסטוריית מפגשים סינתטית, מטרות ומגמות שונות. כל הפרופילים והמפגשים מסומנים כהדגמה, אינם נספרים בתכנון של ילדים אמיתיים ואינם מחליפים או מוחקים רשומות קיימות. לחיצה חוזרת אינה יוצרת כפילויות. נתוני ההדגמה נשמרים בדפדפן עד שמוחקים אותם או את כלל הנתונים.

לבדיקת האלגוריתם בחדר אמיתי פותחים `dev/onsets.html` דרך Live Server; לבדיקות אות סינתטיות פותחים `dev/tests.html`. אלה דפי פיתוח, לא קישורים במסכי האפליקציה. במצב סימולציה, משך המשימות והמעברים מותאם למשך המתוכנן כדי לבדוק גם את תקציב הזמן; במפגש אמיתי אין הוספת זמני המתנה מלאכותיים.

**מסלול ללא מילים** (מסמנים בכרטיס הילד): בהד מוחאים כפיים, במילת הקסם מוחאים או משמיעים צליל בתגובה למטרה (המערכת אינה מזהה מילים), ובשאלות התחושה הילד מצביע על כרטיס והסייעת מתעדת את הבחירה.

## מה הילד רואה

במהלך המפגש הילד רואה את טומבי על כל המסך (הדפדפן עובר למסך מלא), בלי פאנל הסייעת, הגדרות או דוחות. טומבי מוביל את המפגש בקול והפה שלו זז כשהוא מדבר: אזור הלסת נפתח ונסגר, ולא מסתמך רק על החלפת ציורים כמעט זהים. המצמוץ מכסה את העיניים במשטח חלק בגוון הפרווה. לפי המשימה יכולים להופיע תמונת משימה, סרגל התקדמות או בחירות תמונה; אין שימוש באימוג׳י כתמונת משימה. כשהילד משמיע קול, טומבי זוהר, וכשהוא מצליח, טומבי מתקרב וניצוצות עפים ממנו.

## פאנל הסייעת

הפאנל נסתר מהילד. פותחים אותו בלחיצה ארוכה (שנייה) על הפינה העליונה בצד שמאל של המסך, או במקש `A`. בפאנל:

- התקדמות בשלבים, מה טומבי אומר עכשיו, ותצוגה חיה של המשימה (מקצב, עוצמה, צפרדעים, נחש).

- **הילד הגיב** (`רווח`): מסמן תגובה ידנית כשהמיקרופון פספס.
- **חזרה על ההוראה** (`R`), **השהיה** (`P`), **דילוג על שלב** (`N`), **סיום מפגש**.
- **עזרה שנתתי:** מילולית, הדגמה, רמז או הצבעה, פיזית. כל לחיצה נרשמת לדוח העצמאות.
- מד קול חי, עם קו של רעש הרקע (שחור), סף ההאזנה (כתום) והערכה אם זה קול של ילד או של מבוגר.

## הבדלה בין הילד לסייעת

קול שגובהו (F0) נמוך מהסף (ברירת מחדל 210 הרץ) נחשב קול של מבוגר ולא נספר. אפשר לכוון את הסף בהגדרות. אם הסייעת עם קול גבוה, כדאי להעלות קצת את הסף ולבדוק במד שבפאנל.

## הדוח

לכל ילד יש דוח עם משפטי סיכום, גרפים לאורך זמן וטבלה של כל המפגשים. דוח ההתקדמות להדפסה נבנה מנתוני המפגשים השמורים, בפריסת A4 בעברית מימין לשמאל, עם טקסט חי וגרף ציונים וקטורי — לא כתמונת מסך. בגרף מוצג ממוצע הציונים הזמינים בארבע משימות בכל מפגש; מפגשי סימולציה אינם נכללים. לשמירת PDF יש לבחור **שמירה כ-PDF** בחלון ההדפסה. מהדוח אפשר:

- **להדפיס או לשמור כ-PDF** ולשלוח למטפלת ולהורים.
- **להעתיק את הסיכום** כטקסט.
- **לשלוח במייל**: נפתחת טיוטה בתוכנת המייל שלך. שום דבר לא נשלח בלי שתלחצי "שלח".
- **לייצא ל-CSV** ולפתוח באקסל.

טבלת המפגשים מציגה לכל משימה את התחום, הציון, הרמה, ובמידת הזמינות את המדדים הגולמיים; CSV כולל גם את מדדי המשימות החדשות בעמודות נפרדות. תוצאות עם ביטחון נמוך מ־60% מסומנות כזיהוי חלקי.

סדר המפגש נשען על רשימת משימות. כברירת מחדל הוא נשאר כמו קודם; בכל מפגש חדש נשמרים מפתחות המשימות והסדר ששימש אותו, לצד תוצאות המשימות תחת אותם מפתחות, כך שמפגשים ישנים ממשיכים להופיע בדוחות.

## נתונים ופרטיות

- ללא סנכרון מוגדר, נתוני הילד והמפגשים נשמרים רק בדפדפן שבו משתמשים במערכת (localStorage). כאשר סנכרון עתידי יופעל, יועלו רק פרופיל המשחק ומדדים מסוננים; תכונות קול, הקלטות ונתוני אימון אינם נשלחים.
- **כדאי לגבות** מדי פעם: הגדרות ← גיבוי לקובץ. אפשר לשחזר מקובץ גם במחשב אחר.
- אודיו של הילד נשמר רק במאגר זמני בזיכרון לצורך הניתוח, ולא נכתב ל־localStorage, ל־IndexedDB או לקובץ. אפשרות הקלטת שורות קול למטפלת שומרת את הקלטות המטפלת בנפרד ב־IndexedDB; אין בהן הקלטות של הילד.

## כיול בשטח

- **רגישות** (הגדרות): כמה dB מעל רעש הרקע נחשבים קול. ברירת המחדל היא 12. בחדר רועש מעלים, ולילד שקט מאוד מורידים.
- **יעד לנחש:** ברירת המחדל היא הגיל ועוד שנייה אחת. אפשר לקבוע יעד קבוע.
- הספים נבחרו כנקודת התחלה סבירה, וכדאי לכוון אותם אחרי כמה מפגשים אמיתיים.
- משימות הקשה מכיילות רצפת רעש באחוזון 15 במשך שתי שניות ומקפיאות אותה בזמן המדידה. אירוע עם SNR מתחת ל־12 dB מסומן לחזרה.
- לזיהוי onset משתמשים ב־FFT של 512 נקודות, צעד של 10 ms, עשרה פסים לוגריתמיים, חלון שיא של 30 ms וממוצע קודם של 100 ms. מרווחי onset מינימליים תלויי משימה.
- בכיול שמע משתמשים בצ'ירפים של 3.5 kHz; jitter מעל 10 ms או פחות מ־7 סמנים שזוהו מורידים את ביטחון התזמון. המדידה תלויה במכשיר, ברמקול, במרחק וברעש החדר.
- תכונות מחלקת הצליל, גבולות המחלקות, חלון ה־retrigger, ההפרדה בין מחיאת כף/רקיעה/הקשה, ותגובת המיקרופון לרצפה ולמיקום הם השערות תכנון שדורשות אימות מול תיוג וידאו בפיילוט. המדדים אינם אבחוניים.

**ספים ספציפיים למשימות לאימות בפיילוט** (כל הערכים האלה הם ספי תכנון, לא נורמות קליניות):

|---|---|

| מחיאה / רקיעה | רקיעה מתחת ל־300 Hz, לרוב `F + 12 dB`, מרווח onset של 200–220 ms; מחיאה בתחום 0.5–3 kHz, מרווח 130 ms |

| מילת הקסם | חלון תגובה של 2,500 ms, 9 ניסיונות go ו־3 no-go; תגובה שנמשכת פחות מ־250 ms ב־no-go נרשמת כתיקון עצמי; שינויי קול/צליל וכוכב/ירח דורשים בדיקת הבנה |

בפיילוט יש לרשום לכל סף את המכשיר, מרחק המיקרופון, סוג החדר, רעש הרקע, החלטת המטפל/ת מול הווידאו ושיעור הזיהויים השגויים. במיוחד יש לבדוק אם חלונות התזמון וה־SNR נשארים תקפים עם מיקרופונים ומערכות הפעלה שונות.

## כלי פיתוח לאודיו

פותחים ב־Live Server את `dev/tests.html` לבדיקות אות סינתטיות, או את `dev/onsets.html` לצפייה חיה ב־ODF, בפסי התדר, ברצפת הרעש ובאירועים. הדפים אינם מקושרים לממשק הטיפולי.

## בדיקות ציור של הסימולציה

פותחים ב־Live Server את [dev/simulation-qa.html](dev/simulation-qa.html) לתצוגת האנימציה, ואת [dev/simulation-render-tests.html](dev/simulation-render-tests.html) לבדיקות פיקסלים דטרמיניסטיות של הקנבס הסופי. הבדיקות מוודאות ששכבת הפה אינה מסתירה את נשימת החזה, שאין שקיפות בתפר המסכה, שהראש והרגליים נשארים יציבים, שמרקם הסנטר המקורי נשמר ושהפה והמצמוץ פועלים.

שכבת הפה בסימולציה שקופה מחוץ למסכת הפה, ואינה מכסה את כל מלבן החיתוך. אין לכווץ את חיתוך הפה לגובה קטן מהמקור: הכיווץ דוגם פרווה ירוקה מהחזה אל הסנטר ויוצר כתם שלא נמצא בתמונת המקור. בדיקות האודיו לבדן אינן בודקות את הציור.
